# 技术路线

- 论文题目：基于 FreeRTOS 的多传感器智能环境监测与远程控制方法设计与实现
- 学生：李钦颖（202319120808）　指导教师：曾维
- 版本：v0.1（2026-10-04 初始化，随设计推进更新）

## 1. 总体思路

采用「感知层 — 网络层 — 平台层 — 应用层」四层结构，以 FreeRTOS 多任务软件架构为核心，把课程实训中常见的裸机轮询智能家居程序升级为任务解耦、可量化评估实时性的嵌入式物联网系统，并通过对照实验体现毕业论文相对课程实训的技术增量。

```text
传感器组 -> STM32(FreeRTOS: 采集/处理/控制/报警/通信任务) --UART/AT--> ESP8266 --WiFi/MQTT--> Broker --> 上位机/云平台（展示、下行控制）
                ^                                                                    |
                └──────────────────────────── 执行器（继电器/风扇/声光报警器）<──下行指令──┘
```

## 2. 硬件方案

- 主控：STM32（具体型号待定，优先选用已有开发板，如 STM32F103/F407 系列）；
- 联网：ESP8266（ESP-01S 或 NodeMCU），通过 UART 连接 STM32，使用 AT 指令收发 MQTT；
- 传感器（不少于 3 类）：温湿度（如 DHT11/AHT20/SHT30）、光照（BH1750/光敏）、可燃气体/烟雾（MQ-2）等，按实际物料确定；
- 执行器：继电器、LED、有源蜂鸣器、小风扇等；
- 调试与测量：串口打印、逻辑分析仪/示波器 GPIO 翻转测时、PC 端 MQTTX/订阅脚本打时间戳。

## 3. 软件与任务架构（FreeRTOS）

| 任务 | 职责 | 触发/周期 | 优先级（初定） | 同步机制 |
|---|---|---|---|---|
| 采集任务 SensorTask | 周期读取各路传感器，封送数据帧 | 周期（如 1 s） | 高 | 发送至数据队列 |
| 处理任务 ProcessTask | 数据校验、阈值判断、产生报警标志 | 队列阻塞接收 | 中高 | 从队列取数；事件位/信号量通知报警 |
| 通信任务 CommTask | 驱动 ESP8266 完成 MQTT 连接、发布、订阅、断线重连 | 事件/队列驱动 | 中 | 命令队列；连接状态信号量 |
| 控制任务 CtrlTask | 解析下行控制指令，驱动执行器并回传执行结果 | 下行指令到达 | 中 | 指令队列 |
| 报警任务 AlarmTask | 本地声光报警与报警事件上报，含解除/迟滞策略 | 报警事件 | 最高 | 事件位/二值信号量 |

- 至少使用消息队列与信号量中的一种（计划两者均使用：队列传数据、信号量/事件组做同步）；
- 关键区与共享资源（UART、I2C 总线）使用互斥量保护；
- 看门狗（IWDG/任务看门狗）作为异常恢复手段纳入设计。

## 4. 通信与远程控制

- 协议：MQTT（TCP/TLS 视条件而定），Broker 使用本地 EMQX/Mosquitto 或公共测试 Broker，实验中固定并记录；
- Topic 初设：
  - 上行遥测：`dev/202319120808/telemetry`
  - 上行报警：`dev/202319120808/alarm`
  - 下行控制：`dev/202319120808/cmd/down`
  - 控制回执：`dev/202319120808/cmd/up`
- 报文：JSON（字段含设备号、时间戳、各传感器值、报警标志等），字段定义在 `data/metadata/`；
- 远程控制闭环：平台下发指令 → CtrlTask 执行 → 回执上报；
- 拓展：断网期间数据写入本地缓存（如片上 Flash/外部存储），恢复后按时间序补传（EX-1）。

## 5. 报警与异常处理

- 阈值可配置（存于 `configs/`），支持越限报警与恢复迟滞，防止抖动误报；
- 异常工况至少覆盖一种：网络断开/MQTT 掉线（重连策略与状态机）、传感器断线或读数超量程（数据有效性标记与降级运行）；
- 记录异常注入方法、系统表现、恢复时间与数据完整性。

## 6. 测试与评价指标

| 指标 | 定义/测法 | 输出 |
|---|---|---|
| 任务响应时间 | 事件发生（如指令到达/越限）到对应任务开始执行的时间，GPIO 翻转 + 逻辑分析仪测量 | 分布与最大值，满足周期截止 |
| 采样周期稳定性 | 实际采样间隔相对设定周期的抖动（均值/最大偏差/标准差） | 抖动可控、无丢采 |
| MQTT 延迟 | 终端发布到订阅端收包的时间戳差 | 分周期/QoS 统计均值、P95 |
| MQTT 成功率 | 成功收到报文数 / 发布报文数（多轮、足够样本） | 成功率与失败原因分类 |
| 报警响应 | 越限时刻到本地报警动作与报警消息到达平台的时间 | 测量结果 |
| 资源占用（拓展） | CPU 占用率、任务栈高水位/堆使用 | 分析结论 |

对照设计：相同硬件与采样周期下，实现裸机轮询 Baseline，与 FreeRTOS 版本对比响应时间、稳定性与并发负载下的表现。

## 7. 技术选型

- 固件：FreeRTOS（C）、STM32 HAL/LL、STM32CubeMX 初始化；
- ESP8266：官方 AT 固件 + MQTT AT 指令（或评估轻量 MQTT 客户端移植方案，二选一并记录理由）；
- 平台端：MQTTX 验证 + Python（paho-mqtt）脚本做自动化收包计时与简单看板；
- 数据分析：Python（pandas / matplotlib），原始数据入 `results/`，脚本入 `scripts/`。

## 9. 主要风险与对策

- 风险：ESP8266 AT/MQTT 稳定性影响通信指标 → 先固化固件版本与重连状态机，通信失败分类记录；
- 风险：测时手段不精确 → 统一使用 GPIO 翻转 + 逻辑分析仪/时间戳脚本双轨测量；
- 风险：任务优先级设计不当导致饿死/抖动 → 通过 EXP-002 与拓展抖动分析迭代优先级与周期参数；
- 风险：硬件物料不确定 → 2026-11 前冻结物料清单并按 MR-1 验收。
